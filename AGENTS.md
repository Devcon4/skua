# skua agent guide

skua is the glue application that lets devs run long-running coding agents in a shared
Kubernetes cluster and orchestrate them from local omp: fan written proposals out to remote
agents, fix GitHub issues, and similar batch work. It is one Go module
(`github.com/Devcon4/skua`, Go 1.27, controller-runtime, agent-sandbox API types) that builds
one static `skua` binary and one distroless `skua` image holding the operator, `skua-api` and
the in-sandbox runner, plus a TypeScript omp extension. Design work lives in `docs/scratch/`,
and decisions land in `docs/adr/` once made.

## Commands

- `mise install`: installs the pinned Go and tool binaries from `mise.toml`. Make is the
  entry point and expects them on `PATH`, for example through `mise activate` or
  `mise exec -- make <target>`. `mise run <task>` is an optional wrapper that calls `make`.
- `make build`: static binary at `bin/skua`.
- `make test`: unit, envtest and in-process integration tests with `-race`; downloads the
  envtest assets into `bin/`. `tools/testbudget` prints the slowest tests and fails when the
  run takes longer than `TEST_BUDGET` seconds (default 60).
- `make lint`: golangci-lint from mise.
- `make test-e2e`: creates the kind cluster `skua-dev`, builds and loads the images, deploys,
  runs `./test/e2e/...` and deletes the cluster. `E2E_KEEP=1` keeps the cluster and
  `E2E_ARGS` adds `go test` flags.
- Every kind and kubectl command uses `KUBECONFIG=/tmp/skua-dev.kubeconfig` or
  `--kubeconfig /tmp/skua-dev.kubeconfig`, never `~/.kube/config`.
- `SKUA_DEPLOY` picks the install path for `make deploy` and `make test-e2e`: `helm` runs
  `make deploy-chart` and is the `test-e2e` default; `kustomize` runs `make deploy-kustomize`
  and is the `deploy` default.
- `make helm-lint`: strict `helm lint` of `charts/skua` with both CI values files.
- `make test-chart`: chart render tests in `test/chart`.
- `make crds-bundle`: all CRDs in `dist/skua-crds.yaml`.
- `make lint-ci`: zizmor and actionlint on the workflows, then the pin checks in `test/pins`.
- `make check-agent-sandbox-upgrade`, `make check-flux-example`, `make check-ingress-stream`:
  install checks, each in its own kind cluster and kubeconfig under `/tmp`.
- `docs/development.md` lists every target and switch.

## Harness

- Harness files live under `.agents/` wherever omp reads that location, and under `.omp/`
  only where it does not.
- Rules: `.agents/rules/`: `adr`, `gh-writing`, `minimal-comments`, `plain-voice`, all
  always on. omp dedupes rules by name and its user-level rules outrank `.agents/rules`, so
  a repo rule here cannot override a user rule of the same name. A repo override goes in
  `.omp/rules/<name>.md`.
- Hooks: `.omp/hooks/pre/gh-writing.ts` blocks `gh pr` and `gh issue` writes until the
  session has read the `gh-writing` skill. It is a read-gate, not a linter.
- Skills: `.agents/skills/`: `adr`, `code-review`, `gh-writing`, `plain-voice`,
  `scratch-docs`. omp, Codex and Copilot read this location. omp namespaces a repo copy when
  a user-level skill has the same name.
- Git and cluster mutations are the dev's: print the command, do not run it.

## Code conventions

- Prefer the Go standard library. The exception is security, cryptography and published
  protocols: JWT and JWS, OIDC, signing, token exchanges, JSON-RPC and MCP, JSON Schema,
  semver, retry and backoff. These use an industry-standard library and are never
  hand-rolled, because they are more complicated than they look. Examples in use:
  `go-oidc`, `go-jose`, `ghinstallation`, `santhosh-tekuri/jsonschema`, `Masterminds/semver`.
- Go and TypeScript: at most three nested blocks, no `else` or `else if`, early return, and
  conditions, steps and types named for the domain (`runIsTerminal`, `tokenNeedsRemint`).
  ESLint enforces this for TypeScript; `revive`, `nestif`, `gocognit` and review for Go.

Layout (ADR 0007):

1. **Contract** (`internal/contract/...`, `api/v1alpha1`) holds the types and names that
   two or more components agree on. It imports no component. A string two components share,
   such as an endpoint path, a refusal reason or a pod env name, is one exported constant
   here.
2. **Integration** (`internal/integration/...`) holds clients of one external system, with
   no skua logic. The Kubernetes scheme is `kube.Scheme()`.
3. **Components** are `internal/operator`, `internal/api` and `internal/runner`. A
   component root holds wiring and its process lifecycle only: it maps its own `Deps` onto
   each slice's `Deps`, calls the slice's `Setup` (operator) or `Register` (api), and runs
   the manager or server with its health probes and shutdown. api slices register on a small
   `Handle(pattern string, h http.Handler)` interface, so they never import the root.
4. **Slices** import contract, integration and their component's support packages, a
   closed list: `patch` and `condition` for the operator, `auth`, `hub` and `agentrun` for
   the api. A slice never imports a sibling slice or its root. A slice that needs another
   declares the interface it uses, and the root passes the implementation in.
5. **Files** hold one concern each and are named for it. Review flags a file over 300
   lines. In an HTTP slice each command (`create.go`, `steer.go`) and each query (`runs.go`,
   `events.go`) is its own file. Unit tests mirror the source files.
6. **Tests:** unit tests sit beside the code, with no API server and no network beyond
   `httptest`. Every envtest test is a black-box suite under `test/integration/<area>` that
   uses only exported APIs, and only those suites import `internal/testenv`. An operator
   suite calls one slice's `Setup`, an api suite builds the server with `api.New`, and only
   the stack suite uses `operator.Register`.
7. **Test doubles:** an in-process fake is package `<pkg>test` in `<pkg>/<pkg>test/`. A
   process fake lives in `test/fakes/<system>/` with its Dockerfile: a thin `main.go` over a
   `<pkg>test` library, or a `package main` split one concern per file when nothing
   in-process uses it.
8. **Enforcement:** `test/layout` runs in `make test`. It reads
   `go list -deps -test -json ./...` and fails when a contract package imports a component,
   a slice imports a sibling, its root or a package outside its support list, `testenv` is
   imported outside `test/integration`, or a fake is not package `<pkg>test` in
   `<pkg>/<pkg>test/`. Review checks the rest: rule 5, and that `internal/` and `cmd/` never
   import `tools/` or `test/`.

- The omp extension follows the same layout in `extension/src/`: `contract`, `integration`,
  `support`, and the slices `relay` and `commands`, wired only in `extension/index.ts`. Unit
  tests sit beside the code and are named `*.spec.ts`; fakes live in `extension/test/fakes/`.
  These rules are checked in review, not by a test.

## Project conventions

- `skua-operator` and `skua-api` declare no volumes and read their config from env
  `SKUA_CONFIG` (ADR 0004: results live in `status.result` and git, never on a volume).
  `test/chart` and `test/manifests` fail on a volume.
- CRDs ship outside the chart, as `dist/skua-crds.yaml`. `make generate manifests` output is
  committed, and CI fails when regenerating changes the tree.
- GitHub Actions are pinned by full commit SHA with a `# vX.Y.Z` comment, images by
  `@sha256:` digest, and tool binaries by exact version in `mise.toml`. zizmor enforces the
  actions; `test/pins` enforces the images and that the omp pin in `mise.toml` equals
  `extension/omp-range.json` `min`.
- Every kind and kubectl command names its kubeconfig file, never `~/.kube/config`. A test or
  tool that makes its own kind cluster uses its own cluster name and `/tmp/<name>.kubeconfig`.
- Dev tooling is Go under `tools/` or `test/`, or a maintained tool pinned in `mise.toml`.
  The repo has no shell scripts beside the Makefile (ADR 0007).
- No long polling anywhere. SSE per the WHATWG spec is the only server push (dev ruling).
- Tests use a fake for every integration (LiteLLM, GitHub, agent-sandbox, OIDC, the agent,
  clocks) and need no API key, GitHub App or real cluster (dev ruling). A new integration
  comes with a fake that reproduces its limits: expiry, budget, dropped streams, 409s, rate
  limits.
- Tests sit at the lowest layer that can show the behaviour: unit, then in-process
  integration (`test/integration/`), then a few kind acceptance tests (`test/e2e/`) for what
  needs a real component. Budgets on a dev box: `make test` 60 s wall, `make test-extension`
  60 s, kind tests about 90 s after cluster setup. Waits use injected clocks or durations.
  A test that cannot meet its budget is redesigned or deleted when another layer covers it.
  No long-test flags and no scheduled CI jobs.
- Every e2e test calls `t.Parallel`; one that changes a profile or needs its own warm pool
  uses `tempProfile`.
- Review rejects per-run env or volumes on a `SandboxClaim`, because either makes
  agent-sandbox skip the warm pool (ADR 0001).
- The GitHub App private key never enters a sandbox. Only minted installation tokens do
  (ADR 0005).
- Installer docs live in `docs/install/`. Developer docs live in `docs/development.md`.

## Writing conventions

- Anything a human reads (chat, docs, PR text, comments) follows `plain-voice`: flat
  declaratives, no em-dashes, no rhetorical cadence.
- Code comments follow `minimal-comments`: none by default, only the closed list it allows.
- A choice that is costly to reverse becomes an ADR under `adr`. A choice that fails the
  significance test is a convention and goes in this file.
- PR bodies, issue bodies, commit messages and branch names follow `gh-writing`. Read the
  skill before writing any of them.
- Never write a secret value anywhere. Name Kubernetes Secrets, tokens and keys by name.

## Scratch documents

Proposals, specs, investigations, findings, notes, brainstorms and matrices live as
short-lived files in `docs/scratch/`. Only proposals are committed, as design history; the
rest are gitignored. None is ever cited
from committed code or durable docs. The `scratch-docs` skill
(`.agents/skills/scratch-docs/`) holds the patterns and workflows; the folder's own
`AGENTS.md` carries the inviolable rules. Durable outcomes are promoted to `docs/adr/`,
`README.md` or this file, and the dev deletes the scratch file.
